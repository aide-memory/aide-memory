## Bug caught during validation

**Missing MCP server bundle.** First pass only bundled CLI + library entries. `src/memory/cli.ts` (the MCP server stdio entry point referenced by `.mcp.json` generated by `aide-memory init`) was not bundled. Install would have succeeded but `aide-memory` MCP server would fail to start.

**Fix:** added `build:dist:mcp` script bundling `src/memory/cli.ts` → `dist/memory/cli.js`, added to `files` allowlist, added to `scripts/verify-package.sh` must-be-present check, added to `package.test.ts` assertions.

**Also caught:** during earlier packing-test iterations, the root `package.json` got overwritten with the aide-memory publish manifest. Restored to the correct aide-v0 dev manifest. This was a local workspace issue, not something that would have leaked into a published artifact, but would have broken future dev flows on this branch.

## What this validates

- **Minified-publish architecture works end-to-end.** CLI, MCP server, and hooks all function correctly from a published + installed tarball.
- **Source is not leaked.** Installation produces only minified bundles + glue.
- **Existing product behavior is preserved.** All commands, MCP tools, and hooks behave identically to the dev version (which uses tsc output).
- **Package size reasonable.** 242 KB compressed / 935 KB unpacked for a full CLI + MCP server + hooks + templates bundle.

## What this does NOT validate

- **Upgrade from 0.1.x / 0.2.0.** This session tested a clean install into an empty project. An in-place upgrade (`npm update -g aide-memory` on a machine with 0.1.1 or 0.2.0 already installed) was not tested. The data format is unchanged so it should Just Work, but a publishing agent should run a quick upgrade smoke test before final release (see `docs/RELEASING.md` Step 7).
- **Concurrent sessions.** Multi-session MCP scenarios were not re-tested. Per memory 151 the architectural invariants (subcommand contract, database format) are unchanged, so prior session-isolation guarantees should hold.
- **Embeddings / Transformers path.** The optional `@huggingface/transformers` dep is dynamic-imported and external. Its runtime path was not exercised in this validation. If semantic recall matters for the release, a validation run with embeddings enabled should be added.
